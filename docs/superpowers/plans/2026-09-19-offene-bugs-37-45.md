## Chapter A: AppModel lifecycle and editor session (#44, #41, #42)

Conventions verified in the repo: tests use Swift Testing (`import Testing`, `@Suite`, `@Test`, `#expect`), `@MainActor struct` suites, `@testable import OpenZonrApp` / `OpenZonrCore`, and the fixtures in `Tests/OpenZonrAppTests/Support/AppModelFixtures.swift` (`modelWithLoadedConfiguration`, `TempConfiguration`). Comments in the repo are German; new comments below follow that. Line numbers were verified against the current tree (they match the issues).

Facts the design rests on (all read from code):
- `AppModel.refreshPermission` (`AppModel.swift:179-196`) calls `startEngineIfPossible()` on every 2 s tick while access is usable. `startEngineIfPossible` (`:279-296`) ends with an unconditional `dropzones.restart()`. `WatchEngine.start()` is idempotent (`guard !isRunning`), so the engine part is harmless; the restart is the bug. When access is lost, only `engine?.stop()` runs; the dropzone tracker keeps running.
- `dropzonesEnabled` setter (`:317-331`) writes into the cached `document` and skips `save()` when `document != nil`; the getter reads `configuration`. `PanelPresenter` (`:16`, `:29-32`) keeps windows after close and nothing ends `AppModel.document`, so "closed but cached" is indistinguishable from "open".
- `ConfigurationDocument.save()` (`:126-140`) writes without looking at the file; `reloadConfiguration()` (`:236-264`) never touches `document`; `editorDocument()` (`:407-413`) returns the cached one.
- Other readers use `model.document?.configuration ?? model.configuration` (DropzoneController `:116`, `:213`, `:239`; ZoomButtonMenu `:88`, `:246`); they keep working unchanged, because after this chapter the cached document can no longer be stale.

Task order: #44 first (independent), then #41 (menu toggle, needs only a small `ConfigurationDocument` method), then #42 in two tasks (document baseline, then AppModel wiring plus one line of UI).

```swift
    private func startEngineIfPossible(restartDropzones: Bool = false) {
        guard let configuration else { return }

        var created = false
        if engine == nil {
            let engine = WatchEngine(configuration: configuration, dryRun: false)
            engine.isPaused = isPaused
            engine.onChange = { [weak self] in
                self?.syncFromEngine()
            }
            self.engine = engine
            created = true
        }

        if let engine { platform.startEngine(engine) }
        // Dragging follows the engine: both need the same permission and the
        // same configuration, and a drop is placed by the engine itself. Neu
        // aufgesetzt wird nur, wenn der Engine neu ist (Reload) oder der Aufrufer
        // einen Übergang meldet — sonst läuft der bestehende Tracker weiter.
        if created || restartDropzones { dropzones.restart() }
        syncFromEngine()
    }
```

**Interfaces:**
- Consumes: `AppModel.makeDocument(for:)`, `ConfigurationDocument.save()`, `AppModel.reloadConfiguration()`, `AppModel.reportPinFailure` is NOT used (see below).
- Produces:
  ```swift
  extension ConfigurationDocument {
      /// Wendet eine betriebliche Änderung (Menü-Schalter) auf Arbeitskopie UND Ausgangsstand an.
      func applyOperational(_ edit: (Configuration) -> Configuration)
  }
  // AppModel.dropzonesEnabled: getter unchanged (effective = loaded runtime config); setter persists immediately.
  ```

Semantics (recommended, see Open decisions 2): the menu toggle is an operational setting. It takes effect immediately and is persisted immediately, exactly as in the "editor never opened" path today, and it is independent of the editor. The file written is always "loaded configuration plus this one flag" (never the editor's unsaved edits). If a cached document exists, the same flag is applied to both its working copy and its baseline, so unrelated unsaved edits stay, and the document does not turn dirty because of the toggle. The displayed value is the getter, which reads the runtime configuration, so it is by construction the effective state; on a failed write nothing changes and the menu keeps showing the old value plus the failure message. Failure is surfaced through `lastPinMessage`/`lastPinFailed` (the channel the existing toggle code already uses); the menu shows that line.

```swift
    var dropzonesEnabled: Bool {
        get { configuration?.defaults.dropzones.enabled ?? false }
        set { setDropzonesEnabled(newValue) }

    /// Betriebliche Einstellung: wirkt sofort und wird sofort gesichert — mit
    /// oder ohne Editor-Sitzung. Geschrieben wird immer „geladene
    /// Konfiguration plus dieser Schalter“, nie der ungesicherte Editorstand.
    /// Eine vorhandene Sitzung bekommt denselben Schalter in Arbeitskopie und
    /// Ausgangsstand, damit ihre eigenen ungesicherten Änderungen bleiben.
    private func setDropzonesEnabled(_ enabled: Bool) {

        let previous = base.defaults.dropzones.enabled
        guard previous != enabled else { return }
        base.defaults.dropzones.enabled = enabled

        // Zuerst die Sitzung anpassen: das anschliessende Neuladen (onSave)

            var c = c
            c.defaults.dropzones.enabled = enabled
            return c

        let writer = makeDocument(for: base)
        guard writer.save() else {
            document?.applyOperational { c in
                var c = c
                c.defaults.dropzones.enabled = previous
                return c
            }
            lastPinMessage = writer.saveProblem ?? "Speichern fehlgeschlagen."
            lastPinFailed = true
            return
        }
        // `onSave` hat neu geladen und dabei den Tracker neu aufgesetzt.
    }
```

```swift
    ///
    /// Errors are kept rather than thrown: the save button lives in a window
    /// whose only sensible reaction is to show what went wrong, right there.
    /// Ist die Datei seit dem Laden außerhalb geändert worden, wird nicht
    /// geschrieben (verlorenes Update), ausser der Nutzer verlangt es
    /// ausdrücklich.
    @discardableResult
    func save(overwritingExternalChanges: Bool = false) -> Bool {
        if !overwritingExternalChanges {
            if fileChangedOnDisk { refreshFromDisk() }
            if hasExternalChange {
                saveState = .failed(Self.externalChangeMessage)
                onExternalChange?()
                return false
            }

            baseline = Self.bytes(at: url)
            original = configuration
            hasExternalChange = false
            saveState = .saved(Date())
            onSave?(configuration)
            return true
        } catch let error as ConfigurationStoreError {
            saveState = .failed(error.description)
            return false
        } catch {
            saveState = .failed("Speichern fehlgeschlagen: \(error)")
            return false
        }

    /// Gleicht die Sitzung mit einem frisch geladenen Dateistand ab.
    ///
    /// Sauber: der Dateistand wird übernommen. Schmutzig: die Arbeitskopie
    /// bleibt, der Ausgangsstand (Ziel von „Verwerfen“) wird der Dateistand,
    /// und weicht die Arbeitskopie davon ab, ist Sichern gesperrt.
    func reconcile(with disk: Configuration, bytes: Data?) {
        baseline = bytes
        if !hasUnsavedChanges {
            guard disk != configuration else { hasExternalChange = false; original = disk; return }
            configuration = disk
            original = disk
            report = store.validate(disk)
            findings = FindingIndex(report)
            saveState = .unchanged
            hasExternalChange = false
            return
        }
        original = disk
        hasExternalChange = configuration != disk
        if configuration == disk {
            saveState = .unchanged
        } else if case .failed = saveState {
            // Die Meldung des gescheiterten Sicherns bleibt stehen.
        } else {
            saveState = .modified
        }
    }

    /// Die Datei lässt sich nicht (mehr) laden. Sichern bleibt gesperrt, bis der
    /// Nutzer ausdrücklich überschreibt; die Arbeitskopie bleibt erhalten.
    func noteUnreadableDisk(bytes: Data?) {
        baseline = bytes
        hasExternalChange = true
    }

    private func refreshFromDisk() {
        let bytes = Self.bytes(at: url)
        if case let .loaded(disk, _, _) = store.load(at: url) {
            reconcile(with: disk, bytes: bytes)
        } else {
            noteUnreadableDisk(bytes: bytes)
        }
    }
```

## Open decisions

1. **Dirty editor meets a newer file (#42).** Task A3/4 are written against: keep the user's edits, block "Sichern", show one sentence, and offer two explicit ways out: "Verwerfen" (take the file) or "Trotzdem sichern" (overwrite). Cost: one conditional button; the user cannot combine both sides. Alternatives: (a) always keep mine / overwrite silently (zero UI, but this is the reported data-loss bug); (b) always take the file and drop edits (safe for the file, loses unsaved work without asking); (c) a field-level three-way merge prompt (best result, large: needs a diff model over rules/roles/profiles/displays and a merge UI, realistically its own issue).
2. **Meaning of the menu toggle (#41).** Written against: immediate runtime effect plus immediate persistence, independent of the editor, never writing unsaved editor edits (they stay in the editor). Cost: the toggle rewrites the file each time (already true today without an editor) and, if the user has the same flag changed unsaved in the editor, the menu wins for that one field. Alternatives: runtime-only session toggle (no file write, needs new state that is lost at restart and contradicts the setter's own comment that the file is the truth); writing into the editor document only (today's bug).
3. **Reopening the editor reloads the runtime when the file changed.** `editorDocument()` calls `reloadConfiguration()` (engine stop/start, tracker restart) if the file differs from the session baseline. Cost: opening the editor after an external edit has that side effect, though runtime and file were already inconsistent. Alternative: only refresh the document and leave the runtime until the user picks "Konfiguration neu laden"; cheaper but leaves runtime and editor showing different configurations.
4. **No editor-window close hook.** #41 mentions that closing the editor does not end the session. This chapter does not add a lifecycle (sessions stay cached, and are made safe instead), because unsaved edits surviving a close is the existing, documented behavior ("so that reopening the window does not throw away unsaved changes"). Alternative: ask on close (needs an `NSWindowDelegate` in `PanelPresenter`), not required by any acceptance criterion.

```swift
    public mutating func register(_ window: WindowIdentifier, at placement: ResolvedPlacement) {
        removeFromCurrentZone(window)

        placementsByWindow[window] = placement
        epochs[window, default: 0] += 1
        let key = ZoneKey(display: placement.display, zone: placement.zone)
        occupantsByZone[key, default: []].append(window)
    }

    /// Forgets a window entirely — it was closed.
    public mutating func forget(_ window: WindowIdentifier) {
        removeFromCurrentZone(window)
        placementsByWindow[window] = nil
        manualOverrides[window] = nil
        epochs[window] = nil
    }

    /// Every window that currently holds a zone.
    public var trackedWindows: Set<WindowIdentifier> { Set(placementsByWindow.keys) }

    /// Frees the window's zone but keeps its manual override on record.
    public mutating func release(_ window: WindowIdentifier) {
        removeFromCurrentZone(window)
        placementsByWindow[window] = nil
        epochs[window, default: 0] += 1
    }

    /// The claims a decision made, taken right after it ran.
    ///
    /// `earlier` is a copy of the occupancy from *before* the decision; it
    /// supplies what to restore.
    public func claims(for windows: [WindowIdentifier], since earlier: ZoneOccupancy) -> [OccupancyClaim] {
        windows.map {
            OccupancyClaim(window: $0, epoch: epochs[$0] ?? 0, restoring: earlier.placement(of: $0))
        }
    }

    /// Undoes claims whose window has not been claimed again since.
    public mutating func rollback(_ claims: [OccupancyClaim]) {
        for claim in claims where (epochs[claim.window] ?? 0) == claim.epoch {
            if let previous = claim.restoring {
                register(claim.window, at: previous)
            } else {
                release(claim.window)
            }
        }
    }

    /// Forgets every window of a process — its application terminated.
    public mutating func forgetApplication(processIdentifier: Int32) {
        let doomed = Set(placementsByWindow.keys).union(manualOverrides.keys)
            .filter { $0.processIdentifier == processIdentifier }
        for window in doomed { forget(window) }
    }

    /// Drops what the caller can no longer confirm.
    ///
    /// Occupancy is a claim about the screen, and the screen changes without
    /// telling us: windows are closed, dragged away, or resized by their app.
    /// Checking lazily, right before a decision reads the table, avoids
    /// watching windows after placement.
    public mutating func reconcile(_ status: (WindowIdentifier, ResolvedPlacement) -> OccupantStatus) {
        for (window, placement) in placementsByWindow {
            switch status(window, placement) {
            case .present: break
            case .movedAway: release(window)
            case .gone: forget(window)
            }
        }
    }
```

```swift
import Foundation

/// Owns pending placement work: one live job per window, all of it cancellable.
///
/// Placement is not instantaneous. The retry loop waits before and between
/// writes, and an application that is still laying out its window is exactly
/// why. Work that outlives the decision needs an owner, or "paused" and
/// "stopped" stop being true: a write can land seconds after the user said stop.
///
/// Two independent guards make a job abandon itself:
/// - its own ticket — a newer job for the same window replaced it;
/// - the scheduler `generation` — pause, stop, reload or a profile change
///   called ``cancelAll()``.
/// Cooperative `Task` cancellation is checked as well.
@MainActor
public final class PlacementScheduler {

    public typealias Work = @MainActor (_ isCurrent: @MainActor @escaping () -> Bool) async -> Void

    /// Advances whenever everything is cancelled at once. Delayed callbacks that
    /// are not jobs (the frame-read retry, the observer retry) capture it and
    /// compare before acting.
    public private(set) var generation = 0

    private var nextTicket = 0
    private var currentTicket: [WindowIdentifier: Int] = [:]
    private var live: [Int: Task<Void, Never>] = [:]
    private var windowOfTicket: [Int: WindowIdentifier] = [:]

    public init() {}

    /// Jobs that are still the current one for their window.
    public var pendingCount: Int { currentTicket.count }

    /// Starts `work` for `window`, cancelling any older job for the same window.
    public func submit(_ window: WindowIdentifier, work: @escaping Work) {
        cancel(window)

        nextTicket += 1
        let ticket = nextTicket
        let startedGeneration = generation
        currentTicket[window] = ticket
        windowOfTicket[ticket] = window

        live[ticket] = Task { @MainActor [weak self] in
            let isCurrent: @MainActor () -> Bool = { [weak self] in
                guard let self, !Task.isCancelled else { return false }
                return self.generation == startedGeneration && self.currentTicket[window] == ticket
            }
            await work(isCurrent)
            self?.finish(ticket)
        }
    }

    /// Cancels the job for one window, if any.
    public func cancel(_ window: WindowIdentifier) {
        guard let ticket = currentTicket.removeValue(forKey: window) else { return }
        live[ticket]?.cancel()
    }

    /// Cancels the jobs of every window the predicate selects.
    public func cancel(where matches: (WindowIdentifier) -> Bool) {
        for window in currentTicket.keys.filter(matches) { cancel(window) }
    }

    /// Cancels everything and moves on to a new generation.
    public func cancelAll() {
        generation += 1
        for task in live.values { task.cancel() }
        currentTicket.removeAll()
    }

    /// Returns once every started job — cancelled ones included — has unwound.
    public func idle() async {
        while let task = live.values.first {
            await task.value
        }
    }

    private func finish(_ ticket: Int) {
        live[ticket] = nil
        if let window = windowOfTicket.removeValue(forKey: ticket), currentTicket[window] == ticket {
            currentTicket[window] = nil
        }
    }
}
```

```swift
import Foundation

/// How moving one displaced occupant went.
public enum DisplacementOutcome: Hashable, Sendable {
    case moved(attempts: Int)
    /// Closed, or not known to the caller any more: nothing to move.
    case windowGone
    case failed(PlacementOutcome)
    case cancelled
}

public struct DisplacementReport: Hashable, Sendable {
    public var window: WindowIdentifier
    public var outcome: DisplacementOutcome

    public init(window: WindowIdentifier, outcome: DisplacementOutcome) {
        self.window = window
        self.outcome = outcome
    }
}

public struct PlacementJobResult: Hashable, Sendable {
    public var displaced: [DisplacementReport]
    /// Outcome for the incoming window itself.
    public var outcome: PlacementOutcome

    public init(displaced: [DisplacementReport], outcome: PlacementOutcome) {
        self.displaced = displaced
        self.outcome = outcome
    }
}

/// One incoming window: first move the occupants it displaces, then place it.
///
/// ``ZoneOccupancy`` decides who has to give way and books them at the fallback
/// zone; this type is what makes that booking true. Occupants move first so the
/// incoming window never lands on top of a window that is still there. Every
/// step checks `isCurrent` before it writes, so a pause, stop or newer request
/// lets the job abandon itself between windows and between attempts.
@MainActor
public struct PlacementJob {

    public var placer: RetryingWindowPlacer
    /// Finds the live window behind an identifier, `nil` if it is not known.
    public var windowFor: (WindowIdentifier) -> (any PlaceableWindow)?
    /// Converts a placement into the space the windows are written in.
    public var toWindowSpace: (ResolvedPlacement) -> ResolvedPlacement

    public init(
        placer: RetryingWindowPlacer,
        windowFor: @escaping (WindowIdentifier) -> (any PlaceableWindow)?,
        toWindowSpace: @escaping (ResolvedPlacement) -> ResolvedPlacement = { $0 }
    ) {
        self.placer = placer
        self.windowFor = windowFor
        self.toWindowSpace = toWindowSpace
    }

    public func run(
        window: any PlaceableWindow,
        at target: ResolvedPlacement,
        displacing displacements: [Displacement],
        retry: RetryPolicy,
        isCurrent: () -> Bool
    ) async -> PlacementJobResult {
        var reports: [DisplacementReport] = []

        // An occupant has been on screen for a while: no initial delay.
        let occupantRetry = RetryPolicy(
            attempts: retry.attempts,
            initialDelay: 0,
            interval: retry.interval,
            tolerance: retry.tolerance
        )

        for (index, displacement) in displacements.enumerated() {
            guard isCurrent() else {
                reports += displacements[index...].map {
                    DisplacementReport(window: $0.window, outcome: .cancelled)
                }
                return PlacementJobResult(displaced: reports, outcome: .cancelled(attempts: 0))
            }

            guard let occupant = windowFor(displacement.window), occupant.readFrame() != nil else {
                reports.append(DisplacementReport(window: displacement.window, outcome: .windowGone))
                continue
            }

            let outcome = await placer.place(
                occupant,
                at: toWindowSpace(displacement.newPlacement),
                retry: occupantRetry,
                isCurrent: isCurrent
            )
            let mapped: DisplacementOutcome
            switch outcome {
            case let .placed(attempts): mapped = .moved(attempts: attempts)
            case .cancelled: mapped = .cancelled
            default: mapped = .failed(outcome)
            }
            reports.append(DisplacementReport(window: displacement.window, outcome: mapped))
        }

        let own = await placer.place(window, at: toWindowSpace(target), retry: retry, isCurrent: isCurrent)
        return PlacementJobResult(displaced: reports, outcome: own)
    }
}

extension ZoneOccupancy {

    /// Brings the occupancy in line with what the job actually achieved.
    ///
    /// `claims` are those taken right after the decision (the incoming window
    /// and everyone it displaced). Achieved claims stay, the others are undone.
    /// A claim that a newer request has replaced is left alone by
    /// ``rollback(_:)``.
    public mutating func settle(
        _ result: PlacementJobResult,
        claims: [OccupancyClaim],
        window: WindowIdentifier
    ) {
        var undo: [OccupancyClaim] = []

        for claim in claims {
            if claim.window == window {
                if case .placed = result.outcome { continue }
                undo.append(claim)
                continue
            }

            guard let report = result.displaced.first(where: { $0.window == claim.window }) else {
                undo.append(claim)
                continue
            }
            switch report.outcome {
            case .moved:
                continue
            case .windowGone:
                forget(claim.window)
            case .failed, .cancelled:
                undo.append(claim)
            }
        }

        rollback(undo)
    }
}
```

## Open decisions

1. **How does a manually moved-away window affect occupancy? (#45 "define")**
   - Recommended (written into Tasks 1 and 5): lazy reconciliation at decision time. A placed window whose frame is more than 24 pt away from its zone (`movedAway`) is released from the zone, but its manual-override record is kept and not newly created; a window whose frame cannot be read (`gone`) is forgotten completely. Cost: one AX frame read per tracked occupant per new window (an unresponsive app can block a read for around 3 s, see the Outlook note at `WatchEngine.swift:575-580`); the 24 pt threshold is a heuristic and an app that resizes itself later may be falsely released.
   - Alternative A: observe `kAXMovedNotification` / `kAXUIElementDestroyedNotification` per window. Exact and no read at decision time, but adds an observer per placed window and is the "watching after placement" behavior the concept rules out.
   - Alternative B: additionally call `markManuallyOverridden` when a move-away is detected. This finally gives that API a producer and makes rules stand down for such windows, but it misclassifies app-initiated moves as user intent and changes visible behavior beyond this issue. Would be its own issue.
   - Alternative C: do nothing for move-away (only closed/terminated). Cheapest, leaves stale zone claims that displace windows nobody sees there.

2. **What if a displaced occupant cannot be moved to the fallback zone? (#40)**
   - Recommended (Task B4): move occupants first, then place the incoming window regardless. A failed occupant keeps its claim on the original zone (occupancy records the truth: two windows stacked), the failure is logged as a warning. Cost: the user's rule is honored for the new window while the old one stays visible underneath; no automatic retry.
   - Alternative A: abort the new window's placement when its occupant cannot leave (zone stays exclusive). Preserves "replace" semantics, but one stubborn app (Java toolkit, Magnet fighting back) then blocks placement of unrelated windows.
   - Alternative B: place the occupant into a second fallback (e.g. stack onto the target). Needs a new config concept for a second fallback; more surface than the issue asks.
   - Related sub-choice: moving occupants before the new window adds their retry time (up to `attempts x interval`) in front of the new window's placement; placing the newcomer first would be faster but briefly overlaps.

3. **Should windows placed by drag/pin (`place(dropped:)` and other non-rule paths) claim occupancy?** Recommended: no, out of scope; today they never register, and `reconcile` already corrects their effect on the table if they are moved out of a rule-claimed zone. Cost: a dropped window sitting in a rule zone is invisible to `replace`/`skip` decisions. The alternative (register drops with a claim through the same job path) changes drop semantics and belongs with the drop-zone work.

4. **Should a cancelled job leave a `PlacementRecord`?** Recommended: no, log only (Task B5). Cost: the menu list does not show "abgebrochen" rows for placements the user paused away or that a newer request replaced. Alternative: record `.notExecuted("abgebrochen")`; more diagnostic value but noisy on every reload or profile switch.

### Task C3: Pure movement-evidence classifier (Core)

**Files:**

**Interfaces:**
- Consumes: `WindowFrame`, `ScreenPoint` (both AppKit coordinates; caller flips the AX frame first).
- Produces:
  - `public enum WindowMoveEvidence`
  - `public enum WindowMoveEvidence.Verdict: Hashable, Sendable { case moved, resized, notMoved }`

  - `public static func classify(initial: WindowFrame, current: WindowFrame, pointerFrom: ScreenPoint, pointerTo: ScreenPoint) -> Verdict`

Rule (movement evidence): the window is being *moved* iff its size is unchanged (within 2 pt), its origin moved at least 2 pt, and the origin displacement points the same way as the pointer displacement (positive dot product). Negative cases: unchanged frame (text selection, file drag, scrollbar, any content gesture), size change (edge/corner resize), window moving against the pointer (animation/other cause), sub-threshold jitter. The rule is direction-based, not magnitude-equality-based, because windows are clamped at screen edges/menu bar and some apps lag behind the pointer.

```swift
import Foundation

/// Belegt, dass ein Zug das *Fenster* bewegt und nicht etwas darin.
///
/// Ein AXWindow-Vorfahre unter dem Druckpunkt plus Zeigerweg beweist das nicht:
/// Text markieren, eine Datei ziehen oder einen Scrollbalken ziehen erfuellt
/// beides (#37). Der einzige Beleg, der Fensterzug von Inhaltszug trennt, ist
/// der Fensterrahmen selbst: er folgt dem Zeiger, oder er tut es nicht.
///
/// Rein und ohne AX, damit die Regel headless beweisbar ist. Die Rahmen liefert
/// der Tracker ausserhalb des Tap-Rueckrufs (siehe `EventTapDragTracker`,
/// #26); beide Rahmen und beide Punkte muessen in **AppKit**-Koordinaten sein.
public enum WindowMoveEvidence {

    public enum Verdict: Hashable, Sendable {
        /// Groesse gleich, Ursprung folgt dem Zeiger: das Fenster wird gezogen.
        case moved
        /// Die Groesse hat sich geaendert: Kanten- oder Eckenzug.
        case resized
        /// Kein Beleg (Inhaltszug, Wackeln, Gegenbewegung).
        case notMoved
    }

    /// Groessenabweichung in Punkten, die noch als "gleich gross" gilt.
    public static let sizeTolerance: Double = 2
    /// Ursprungsverschiebung in Punkten, ab der von Bewegung die Rede ist.
    public static let minimumTravel: Double = 2

    public static func classify(
        initial: WindowFrame,
        current: WindowFrame,
        pointerFrom: ScreenPoint,
        pointerTo: ScreenPoint
    ) -> Verdict {
        if abs(current.width - initial.width) > sizeTolerance
            || abs(current.height - initial.height) > sizeTolerance {
            return .resized
        }
        let windowDX = current.x - initial.x
        let windowDY = current.y - initial.y
        guard (windowDX * windowDX + windowDY * windowDY).squareRoot() >= minimumTravel else {
            return .notMoved
        }
        let pointerDX = pointerTo.x - pointerFrom.x
        let pointerDY = pointerTo.y - pointerFrom.y
        // Richtung statt Betrag: Fenster werden am Rand/Menuebar geklemmt, und
        // manche Apps hinken dem Zeiger hinterher.
        return windowDX * pointerDX + windowDY * pointerDY > 0 ? .moved : .notMoved
    }
}
```

## Open decisions

1. **Unreadable AX frame: fail closed or open?** (Task C4: `applyFrameSample` ignores a `nil` frame.)
   - Recommended: fail closed (no overlay, no drop when the app never reports a frame). Cost: an app whose window frame cannot be read never gets drag-to-zone; but such a window also could not be placed by the engine afterwards, so the loss is small and it matches the "no evidence, no placement" intent of #37.
   - Alternative: fail open after N samples (fall back to today's behaviour). Cost: reintroduces exactly the false positives for those apps and hides the failure.

2. **Overlay timing: withhold `.began` until evidence (recommended) or show the overlay immediately and only gate the drop.**
   - Recommended: withhold. Cost: the overlay appears one AX round trip (typically a few ms, up to the #26 peaks for slow apps) after the drag threshold, but a text selection or scrollbar drag never flashes the overlay, and the controller needs no change.
   - Alternative: show at threshold, gate only on release. Cost: keeps the flicker on every content drag (bad UX, what the user sees in #37) and needs controller changes plus a second state.

3. **Resize (edge/corner) drags: treat as "not a move" (recommended) or keep as drag-to-zone.**
   - Recommended: not a move (`.resized`). Cost: a user who resizes a window and releases on a zone no longer gets a placement (today it silently places, arguably a bug). 
   - Alternative: treat resize like move. Cost: the resize gesture triggers placement and pinning exactly like the content gestures the issue wants to eliminate.

## Chapter D: Modus-unabhängige Fallback-Identität (Issue #39)

### Ausgangslage (verifiziert im Code, commit ec34da5)

- `SystemDisplays.swift:39-41` liest `CGDisplayCopyDisplayMode(id).pixelWidth/pixelHeight`. Das ist die **aktuelle** Modus-Größe, obwohl der Kommentar "native" behauptet. Diese Werte fließen in `.fallback(vendorNumber:modelNumber:pixelWidth:pixelHeight:portIndex:)` (Zeilen 47-55).
- `DisplayIdentity` (`Sources/OpenZonrCore/Display/DisplayIdentity.swift`) ist ein `enum: Codable, Hashable, Sendable` mit **synthetisiertem** `==`/`hash`. `SetupFingerprint` hält ein `Set<DisplayIdentity>`; `DefaultProfileResolver.aliases(for:in:)` matcht über ein `[DisplayIdentity: DisplayAlias]`-Dictionary. Jede Änderung an `==`/`hash` wirkt daher automatisch auf Fingerprint, Resolver, `ignoredDisplays` und Validierung (Duplikate).
- Identitäten stehen im JSON unter `displays[].identity` und `ignoredDisplays[]` (`kind: "fallback"` mit `pixelWidth`, `pixelHeight`, `portIndex`). `Configuration.currentVersion == 1`, `ConfigurationMigrator` kennt keine Schritte (`steps: []`). Migrationen sind `MigrationStep`s auf dem rohen `[String: Any]`-Dokument, ein Hop pro Version.

### Welche öffentlichen APIs sind modus-unabhängig?

| Wert | API | Modus-unabhängig? |
|---|---|---|
| Vendor / Model | `CGDisplayVendorNumber`, `CGDisplayModelNumber` | Ja (EDID). |
| Physische Größe mm | `CGDisplayScreenSize` | Ja für echte Panels (EDID), aber für Software-Displays unbrauchbar (siehe Kommentar in `SystemDisplays.looksVirtual`) und **kein** Unterscheidungsmerkmal baugleicher Monitore. Wird deshalb nicht in die Identität aufgenommen. |
| Unit-Nummer | `CGDisplayUnitNumber` | Ja gegenüber dem Modus. Aber: hängt an der Verbindung/Port-Topologie, kann sich beim Umstecken oder Hub-Wechsel ändern. |
| Native Pixelgröße | `CGDisplayCopyAllDisplayModes(id, [kCGDisplayShowDuplicateLowResolutionModes: true])` und `CGDisplayModeGetIOFlags(mode) & kDisplayModeNativeFlag` (`0x02000000`, IOKit `IOGraphicsTypes.h`) | Nur wenn der Treiber das Native-Flag setzt. **Nicht verifiziert**, ob das für serial-lose Monitore (z. B. Samsung C49RG9x über DP/HDMI) zuverlässig der Fall ist; auch ob `CGDisplayModeGetIOFlags` im verwendeten SDK ohne Deprecation-Warnung verfügbar ist, muss der Compiler zeigen. |
| "Größter Modus" als Ersatz | `max(pixelWidth*pixelHeight)` über alle Modi | **Nicht sicher**: skalierte HiDPI-Modi können Backing-Store-Größen über der Panel-Auflösung melden. Deshalb wird dieser Weg bewusst nicht verwendet. |
| Aktueller Modus | `CGDisplayCopyDisplayMode` | Nein (das ist der Fehler). |

Fazit: Vendor, Model und Unit-Nummer sind modus-unabhängig. Die native Pixelgröße ist nur über ein Treiber-Flag zu bekommen und kann fehlen. Daher wird die Identität so entworfen, dass sie **auch ohne verlässliche native Größe** korrekt matcht.

### Entwurf (Empfehlung, siehe Offene Entscheidungen)

1. Die Identität eines serial-losen Monitors ist logisch `(vendor, model, portIndex)`. `pixelWidth`/`pixelHeight` bleiben im Datenmodell und im JSON (kein Schema-Bump), sind aber **nur Anzeigeinformation** und zählen **nicht** in `==`/`hash`.
2. Neu erzeugte Identitäten tragen die native Größe, falls das Native-Flag genau einen Modus markiert, sonst `0 x 0` (unbekannt). Nie die aktuelle Modus-Größe.
3. **Legacy-Kompatibilität durch Matcher statt Migration**: weil Pixelmaße nicht mehr zählen, matcht jede früher gespeicherte Fallback-Identität (egal in welchem Modus aufgezeichnet) ohne Dateiänderung. Begründung gegen eine Migration: (a) ein `MigrationStep` arbeitet auf dem JSON allein und kennt weder Hardware noch den nativen Modus, kann die gespeicherten (evtl. falschen) Pixelwerte also nicht korrigieren; (b) er würde `currentVersion` auf 2 heben und ältere App-Versionen die Datei ablehnen lassen (`unsupportedVersion`), ohne dass das Format sich ändert; (c) Identitäten stehen an mehreren Stellen (`displays`, `ignoredDisplays`), der Matcher deckt alle ab.
4. **Unterscheidung baugleicher serial-loser Monitore**: ausschließlich über `portIndex` (`CGDisplayUnitNumber`). **Grenze**: zwei baugleiche Monitore (gleiches Vendor/Model, Seriennummer 0) sind nur so lange unterscheidbar, wie jeder an "seinem" Anschluss hängt. Werden sie vertauscht, oder ändert sich die Unit-Nummer (anderer Port, Dock, Hub, ggf. Neustart), werden sie verwechselt bzw. nicht erkannt. Das ist gegenüber vorher **keine** Verschlechterung (vorher zusätzlich instabil bei Modus-Wechsel), aber auch keine Verbesserung. Mit öffentlichen APIs gibt es hier keine bessere Quelle; das wird dokumentiert, nicht überspielt.
5. Neue Konsequenz des Matchers: zwei Deskriptoren in einer Konfiguration mit gleichem `(vendor, model, portIndex)` aber verschiedenen Pixelmaßen gelten jetzt als Duplikat; der Resolver nimmt wie bisher den ersten. Praktisch nur eine Altlast aus einem Modus-Wechsel, den der Nutzer bereits als "zwei Monitore" abgelegt hat.

```swift
import Foundation

/// One entry of a display's mode list, reduced to plain values so the identity
/// derivation can be tested without a display attached.
public struct DisplayModeSample: Hashable, Sendable {

    /// `kDisplayModeNativeFlag` from IOKit's `IOGraphicsTypes.h`.
    public static let nativeIOFlag: UInt32 = 0x0200_0000

    public var pixelWidth: Int
    public var pixelHeight: Int
    /// `CGDisplayModeGetIOFlags`.
    public var ioFlags: UInt32

    public var isFlaggedNative: Bool { ioFlags & Self.nativeIOFlag != 0 }

    public init(pixelWidth: Int, pixelHeight: Int, ioFlags: UInt32) {
        self.pixelWidth = pixelWidth
        self.pixelHeight = pixelHeight
        self.ioFlags = ioFlags
    }
}

/// Derives ``DisplayIdentity/fallback(vendorNumber:modelNumber:pixelWidth:pixelHeight:portIndex:)``
/// from values that do not change when the user switches the display mode.
///
/// The current mode is deliberately not an input. The native panel size is only
/// available when the driver flags exactly one size as native; otherwise it is
/// recorded as `0 x 0` (unknown) rather than guessed, because the largest mode
/// can be a scaled backing store larger than the panel. The pixel size is
/// informational only — see ``DisplayIdentity`` equality.
public enum FallbackIdentityDerivation {

    public static func nativePixelSize(from modes: [DisplayModeSample]) -> (width: Int, height: Int)? {
        let sizes = Set(
            modes.filter(\.isFlaggedNative).map { Size(width: $0.pixelWidth, height: $0.pixelHeight) }
        )
        guard sizes.count == 1, let size = sizes.first else { return nil }
        return (size.width, size.height)
    }

    public static func identity(
        vendorNumber: UInt32,
        modelNumber: UInt32,
        unitNumber: Int,
        modes: [DisplayModeSample]
    ) -> DisplayIdentity {
        let size = nativePixelSize(from: modes)
        return .fallback(
            vendorNumber: vendorNumber,
            modelNumber: modelNumber,
            pixelWidth: size?.width ?? 0,
            pixelHeight: size?.height ?? 0,
            portIndex: unitNumber
        )
    }

    private struct Size: Hashable {
        var width: Int
        var height: Int
    }
}
```

## Open decisions

1. **Legacy-Identitäten: Matcher (Empfehlung) oder Config-Migration.**
   - *Matcher (Task D2, geplant):* `==`/`hash` ignorieren Pixelmaße bei `.fallback`. Kosten: `==` ist nicht mehr feldweise, zwei Deskriptoren mit gleichem vendor/model/port aber verschiedenen Pixelmaßen kollidieren als Duplikat (Resolver: erster gewinnt); Pixelmaße im JSON bleiben potentiell veraltet (nur Anzeige). Vorteil: kein Schema-Bump, keine Dateiänderung, greift auch für `ignoredDisplays`, funktioniert auch wenn das Native-Flag fehlt.
   - *Migration (`MigrationStep` 1 -> 2):* Pixelfelder aus allen Identitäten entfernen oder auf 0 setzen. Kosten: `currentVersion` 2, ältere App-Versionen lehnen die Datei ab, Schema-Änderung ohne inhaltlichen Gewinn, kann die falschen Werte nicht durch richtige ersetzen (kennt die Hardware nicht), Dateien werden umgeschrieben. Sinnvoll nur, wenn ohnehin ein anderes Schema-Update ansteht.
2. **Pixelfelder im Datenmodell behalten (Empfehlung) oder entfernen.** Behalten: Format und `--config-fragment`-Ausgabe bleiben lesbar, kein Bruch. Entfernen: sauberer, aber Breaking Change am `DisplayIdentity`-Case (viele Testaufrufe) und faktisch eine Migration; als eigenes Issue nachziehbar.
3. **Unbekannte native Größe als `0 x 0` (Empfehlung) oder größter Modus als Schätzung.** `0 x 0` ist ehrlich, kostet nur Anzeigeinformation. Größter Modus gibt eine Zahl, kann aber (skalierte Backing-Stores) eine falsche native Größe behaupten. Da die Größe nicht mehr matcht, ist der Schaden gering, die Irreführung nicht.
4. **Unit-Nummer als einzige Unterscheidung baugleicher Monitore akzeptieren (Empfehlung) oder zusätzlich IOKit/`IODisplayConnect`-Pfade (Registry-Pfad, `IOServiceMatching("IODisplayConnect")`) erkunden.** Letzteres könnte stabilere Port-Bezeichner liefern, ist aber ohne Hardware nicht bewertbar, weitgehend undokumentiert und gehört in ein eigenes Issue mit Messung. Bis dahin steht die Grenze in der Doku.
